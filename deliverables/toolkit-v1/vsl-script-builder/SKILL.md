# VSL Script Builder

Writes a complete VSL script from an offer. Two endings to choose from:

- **Call-booking** (default) — ends with "book a call." Good for high-ticket
  offers with no price stated on camera.
- **Direct-buy** — ends with "click the button below." Price and guarantee
  are stated on camera.

If it's unclear which fits, ask. A coaching/consulting/done-for-you offer
defaults to call-booking.

## Step 1 — Ask before writing (do not skip this)

A generic VSL converts at zero. The script is built out of the *specific*
fears and desires of one real customer — get those first, in two short
rounds so it doesn't feel like a form.

**Round 1 — the offer**
1. What exactly do they get, and how does it work (the mechanism)?
2. Who is it for, specifically — not "business owners," but a person you
   could picture?
3. What's the outcome, and by when? Push for a real number and a timeframe.
4. What makes you credible to say this? (results, years doing it, proof)
5. Ending: book a call, or buy now? What does the button say?

**Round 2 — what makes it land**
6. What has this person already tried that didn't work? (this becomes the
   part of the script that handles their skepticism)
7. What's the one line, in their own words, that describes what keeps them
   up at night about this problem?
8. What proof exists — screenshots, numbers, before/afters, testimonials?

If some answers don't come, write the script anyway with a clearly bracketed
placeholder like `[ADD YOUR REAL RESULT HERE]`, and list every placeholder
at the end under "Fill these in." Never invent a testimonial, a number, or a
result and present it as real.

If an answer is vague ("more sales," "grow the business"), push once for a
specific version — "from $30k/mo to $100k/mo in 90 days" is the version that
actually writes a script that converts.

## Step 2 — Write the script in this order

| # | Beat | What it does |
|---|---|---|
| 1 | Cold open | Lead with the end result — stop the scroll. |
| 2 | Who this is for | "If you're someone who…" — call out the exact person. |
| 3 | The promise | "In the next few minutes I'll show you…" |
| 4 | Why listen to you | Your credibility, briefly. |
| 5 | Name their failed attempts | What they've tried that didn't work — this earns trust because it shows you understand the problem. |
| 6 | Widen the gap | What their life looks like if nothing changes vs. if this works. |
| 7 | The mechanism | How it actually works, simply. |
| 8 | Proof | The realest evidence available. |
| 9 | Handle the obvious objection | "This isn't X, doesn't require Y, isn't Z" — whatever they'd assume and dismiss it for. |
| 10 | Transition to the offer | Name what's being offered. |
| 11 | The ask | Exact instruction: book the call / click the button. |
| 12 | Risk reversal | Guarantee, or "it's not a sales call" — remove the last hesitation. |
| 13 | Final push | Restate the ask once more, calmly, and close. |

**Length**: aim for 900–1,600 words for a short/cold-traffic VSL, or
1,800–2,600 words for a fuller version that covers every beat with more
proof and story. Ask which the user wants if it matters to them; default to
the fuller version.

## Step 3 — Writing rules

- **Second person, present tense.** "You're sitting there wondering if this
  will actually work" — not "people often wonder."
- **Write like it's spoken, not written.** Contractions, short sentences,
  one idea per line. If a line can't be said in one breath, cut it.
- **Their words, not yours.** If the user described the pain as "getting
  scammed," the script says "getting scammed" — not "risk mitigation."
- **No corporate language.** Cut "leverage," "solutions," "utilize," "in
  today's fast-paced world."
- **Specific beats intense.** "$104,000 last month" lands harder than
  "massive results" — and only use the specific version if it's real.
- Never promise a guaranteed financial outcome ("you WILL make $10k"). Use
  "here's how clients have done it" framing instead.
- Don't make health, money, or legal claims that can't be backed up — flag
  these to the user instead of writing them.

## Step 4 — Deliver in this format

1. **The script** — clean and camera-ready, with beat names as side notes
   (e.g. in brackets) so they're easy to strip out for a teleprompter.
2. **B-roll / proof cues** — inline notes like `[SHOW: testimonial
   screenshot]` at the proof beats.
3. **Fill these in** — a list of every placeholder still in the script.
4. **Runtime estimate** — word count ÷ 150 words per minute.

Deliver as a file the user can open, not just a chat code block.
